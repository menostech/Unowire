# Implementation Plan: Portal Brand Unification + Logout Fix + Claim Your Company

## Global Constraints

- All code, comments, and documentation in English (project is global-facing)
- Frontend-backend separation: Next.js + FastAPI + PostgreSQL
- No frontend automated tests (MVP constraint)
- All middleware must use async/await
- Docker Compose for local dev with `--env-file .env.docker`
- Follow existing code patterns (see referenced files in each task)

## Task 1: Backend — ClaimRequest Model + Migration

**Files:**
- Create: `backend/app/models/claim_request.py`
- Modify: `backend/app/models/__init__.py`
- Create: `backend/alembic/versions/XXXX_add_claim_requests.py` (autogenerated)

**Reference:** `backend/app/models/cable.py` (model pattern), `backend/app/models/equipment.py` (model pattern)

**Steps:**
1. Create `ClaimRequest` model with fields: id (UUID PK), manufacturer_type (String(20)), manufacturer_id (String(100)), contact_name (String(200)), contact_email (String(200)), contact_phone (String(50) nullable), proof_description (Text), status (String(20) default "pending"), reviewed_by (String(100) nullable), reviewed_at (DateTime nullable), created_at, updated_at. Use `from sqlalchemy.dialects.postgresql import UUID` for UUID type, `default=uuid4` for id.
2. Register in `backend/app/models/__init__.py` (add `from app.models.claim_request import ClaimRequest`).
3. Generate migration: `cd backend && alembic revision --autogenerate -m "add claim_requests table"`
4. Run migration: `alembic upgrade head`

**Verification:** Migration applies cleanly, table exists in DB.

## Task 3: Backend — Public Claim Routes

**Files:**
- Create: `backend/app/api/routes/portal_claim.py`
- Modify: `backend/app/main.py` (register router)

**Reference:** `backend/app/api/routes/portal_equipment.py` (route pattern, but NO auth dependency for public endpoints)

**Endpoints:**
- `GET /api/portal/claim/search?q=<query>`: Public (no auth dependency). Search cable_manufacturers + equipment_manufacturers by name ilike, limit 10 each. Return `[{id, name, slug, type}]`.
- `POST /api/portal/claim`: Public (no auth). Accept `ClaimRequestCreate` body. Validate manufacturer exists (check cable_manufacturers or equipment_manufacturers based on manufacturer_type). Return 201 with `{id}`. 404 if manufacturer not found. 422 for validation errors.

**Steps:**
1. Create router with prefix `/api/portal/claim`.
2. Implement search endpoint: if q is empty, return []. Build ilike pattern. Query both manufacturer tables. Combine results.
3. Implement submit endpoint: validate manufacturer exists (conditional on manufacturer_type). Create ClaimRequest with status="pending". Commit. Return `{"id": claim.id}`.
4. Register router in `main.py`.

## Task 4: Backend — Admin Claim Routes

**Files:**
- Create: `backend/app/api/routes/admin_claims.py`
- Modify: `backend/app/main.py` (register router)

**Reference:** `backend/app/api/routes/equipment.py` (admin route pattern with `require_operator`)

**Endpoints:**
- `GET /api/admin/claims`: `require_operator` auth. Optional `status` query filter. Return all claims ordered by created_at desc, with manufacturer_name joined.
- `POST /api/admin/claims/{id}/approve`: `require_operator`. Set status="approved", reviewed_by, reviewed_at. Return updated claim. 404 if not found. 409 if already processed.
- `POST /api/admin/claims/{id}/reject`: `require_operator`. Same as approve but status="rejected".

**Steps:**
1. Create router with prefix `/api/admin/claims`.
2. Implement list endpoint with optional status filter.
3. Implement approve/reject endpoints: check status=="pending" before updating, else 409. Set reviewed_by from admin user id, reviewed_at = datetime.now(timezone.utc).
4. Register router in `main.py`.
